# Система управления кладбищем — Backend

Серверная часть системы для учёта секторов кладбища, мест захоронения, клиентов, сотрудников и заявок на захоронение или бронирование места.

Проект находится в разработке. Реализованы модели данных, репозитории Spring Data JPA, миграции схемы и HTTP API с разделением на контроллеры и транзакционные сервисы. API поддерживает CRUD, архивирование и восстановление записей.

## Предметная область

| Сущность | Назначение |
| --- | --- |
| Customer | Клиенты: ФИО и контактные данные |
| Employee | Сотрудники: учётные данные, роль и признак активности |
| Sector | Сектора кладбища |
| Plot | Места захоронения: сектор, ряд, номер, размеры, координаты и статус |
| Request | Заявки: клиент, место, ответственный сотрудник, данные умершего и стоимость |

Место относится к сектору, а заявка связана с клиентом и местом захоронения. Ответственный сотрудник и данные умершего могут отсутствовать при бронировании. Статус архива хранится отдельно от статусов места и заявки.

## Технологии

- Java 21 и Spring Boot 4.1.1.
- Spring Web MVC — основа HTTP API.
- Spring Data JPA и Hibernate — ORM и доступ к данным.
- PostgreSQL — база данных; H2 — база в памяти для локального запуска и тестов.
- Flyway — миграции схемы базы данных.
- Spring Security — инфраструктура безопасности.
- Jakarta Validation — валидация данных.
- Lombok — генерация геттеров, сеттеров и конструкторов.
- Springdoc OpenAPI / Swagger UI — инфраструктура документации API.
- Spring Boot Actuator — мониторинг приложения.
- Gradle Wrapper — сборка и запуск проекта.
- JUnit 5 и Spring Boot Test — модульные и интеграционные тесты.

## Требования

## Локальный запуск

По умолчанию приложение использует H2 в памяти, поэтому отдельная установка базы данных не требуется. После остановки приложения данные теряются.

Linux / macOS:

```bash
./gradlew bootRun
```

Windows PowerShell:

```powershell
.\gradlew.bat bootRun
```

Приложение запускается на порту `8080`. Пока действует стандартная конфигурация Spring Security: пользователь `user`, пароль генерируется и выводится в журнал при запуске.

## Подключение PostgreSQL

Создайте пустую базу данных и задайте параметры подключения через переменные окружения:

| Переменная | Назначение | Значение по умолчанию |
| --- | --- | --- |
| DB_URL | JDBC URL базы данных | `jdbc:h2:mem:pks_3;DB_CLOSE_DELAY=-1` |
| DB_USERNAME | Пользователь базы данных | `sa` |
| DB_PASSWORD | Пароль пользователя | Пустая строка |

Пример для PowerShell:

```powershell
$env:DB_URL = 'jdbc:postgresql://localhost:5432/pks_3'
$env:DB_USERNAME = 'postgres'
$env:DB_PASSWORD = 'your-password'
.\gradlew.bat bootRun
```

При запуске Flyway применяет миграции из `src/main/resources/db/migration`. Hibernate проверяет соответствие сущностей схеме базы данных.

## HTTP API

| Ресурс | Базовый путь |
| --- | --- |
| Клиенты | `/api/customers` |
| Сектора | `/api/sectors` |
| Сотрудники | `/api/employees` |
| Места захоронения | `/api/plots` |

Для каждого ресурса доступны следующие операции:

| Метод | Путь относительно базового | Операция |
| --- | --- | --- |
| GET | `/` | Список всех записей, включая архивные |
| GET | `/{id}` | Получение записи по UUID |
| POST | `/` | Создание записи, ответ `201` |
| PUT | `/{id}` | Замена предметных полей записи |
| DELETE | `/{id}` | Архивирование, ответ `204` |
| POST | `/{id}/restore` | Восстановление записи из архива |
| DELETE | `/{id}/permanent` | Окончательное удаление архивной записи, ответ `204` |

Запросы и ответы используют JSON. В PUT передаются все обязательные поля;
UUID, дата создания и статус архива через тело запроса не меняются.
Для сотрудников передаётся готовый `passwordHash`, который не возвращается в ответах.
Для места указывается `sectorId` — UUID существующего сектора.
Ошибки валидации возвращают `400`, отсутствующие записи — `404`,
конфликты уникальности, внешних ключей и состояния архива — `409`.

Пример тела запроса для создания клиента:

```json
{
  "fullName": "Иван Иванов",
  "phone": "+79991234567",
  "email": "ivan@example.com"
}
```

Доступ требует аутентификации Spring Security. Для POST, PUT и DELETE также
требуется CSRF-токен стандартной конфигурации Spring Security. Ролевая модель
доступа к операциям пока не настроена.
